# Plantilla de historia de usuario SIGMA-TE

## Estructura base
Como [tipo de usuario],
quiero [acción],
para [beneficio].

## Reglas para redactar
- El usuario debe ser un rol real del sistema.
- La acción debe ser concreta.
- El beneficio debe explicar el valor operativo.
- No debe incluir solución técnica.
- No debe mezclar varias necesidades en una sola historia.

## Ejemplo correcto
Como técnico,
quiero registrar una falla de un equipo,
para dejar trazabilidad del incidente y facilitar su seguimiento.

## Ejemplo incorrecto
Como usuario,
quiero que el sistema use base de datos moderna,
para que funcione mejor.

## Observación
Si la historia describe demasiadas acciones, debe dividirse en historias más pequeñas.
